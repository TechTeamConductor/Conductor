# Conductor HTTP / SSE API (UI ↔ server contract)

The v2 contract (board-native; no Linear). Types live in [`src/types.ts`](../src/types.ts) (`Api*` interfaces). The server binds to `127.0.0.1` only.

## Transport & security (the UI must follow these)

- **Auth.** The browser arrives already signed in: `conductor open` mints a one-time URL that sets an `HttpOnly; SameSite=Strict` session cookie. The UI never sees or handles tokens. Any `401` ⇒ show a full-page "Session expired — run `conductor open` in a terminal" message.
- **Mutations** (`POST`/`PUT`/`DELETE`) must send `Content-Type: application/json` **and** header `X-Conductor-CSRF: <state.csrf>` (value from the latest `GET /api/state`). Missing/incorrect ⇒ `403`.
- **CSP** is `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'`. Therefore: **no inline `<script>`, no inline `style="…"` attributes, no external fonts/CDNs**. Use classes; set dynamic values via `element.style.setProperty('--x', …)` (CSSOM is allowed).
- **Static files** are an exact whitelist: `/` → `ui/index.html`, `/modes.js`, `/app.js`, `/style.css`, `/favicon.svg`. Nothing else is served. `/`, `/modes.js` and `/app.js` need a session; without one, the browser is redirected to `/login`.
- **Errors**: HTTP status + body `{"error":{"code":"…","message":"…"}}` (`ApiError`). Messages are human-readable and safe to show verbatim. Some refusals add `field` (the control the refusal is about, e.g. `"roles.planning.effort"` — only ever allow-listed names) or route-specific extras; `code`, `message` and `field` are never overridden by an extra. `field` is omitted when it does not apply.
- All timestamps are **epoch milliseconds** unless noted. Bodies ≤ 1 MB.

## Read endpoints

### `GET /api/state` → `ApiState`
Everything the dashboard needs in one call (see `ApiState`): `setup` (wizard steps `agents`, `repo`; `complete:false` ⇒ show the setup wizard), `health` (claude/cursor + warnings), `quota.claude`, `engine` (incl. `storageProblem`, `ignored`, `runMode`, `runModeChangedAt`), `settings` (incl. `runMode`, `overriddenByRunMode`, `limitRule`, `limitRuleEffective`), `repos`, `runs` (`ApiRunSummary[]`, newest first, includes closed runs), **`cards`** (cards that have no run yet — Backlog / To do — each `{key,title,lane,kind,note?}`), **`waiting`** `{ total, bulkApprovable, eligible: [{ key, rev, title }] }` (plans in `awaiting_approval`; `eligible` is exactly what "Approve waiting plans" may send — titles redacted), optional `accounts`, optional `home`, `csrf`.

### `GET /api/providers` → `{ providers: ApiProvider[] }`
Every registry provider (`claude`, `cursor`, later `codex`): `state` (`ok | missing | broken-install | not-logged-in | unknown`), `version`/`detail` (what the CLI said — redacted and truncated; render with `textContent`), a **static** `hint` (never CLI text; Conductor shows it and never runs it), `capabilities {readOnly, build, buildIsolationVerified}` — **derived from code, never from config** — the read-only `tier` (`verified | partial | unverified | blocked`), `inUse` (appears in a role chain), `pausedUntil`, `buildVerification` / `isolationCheck` (display only; `isolationCheck.trusted:false` = the check passed but its matchers are not yet validated against a real Codex, so the tier is unchanged). The same list is `ApiState.providers`.

### `GET /api/roles` → `ApiRoles`
`{ roles, choices, needs, toolModels, roleViews, rows, legacyNotices, models }` (everything after `needs` describes the per-job tool, model and effort choices):
- `roles[r]`: exactly the keys `PUT /api/roles` accepts, **always present** (`null`/`false` when unset), so the object round-trips: `providers`, `autoByComplexity` (`null` when unset), `tool` (the tool the model choice was made for — server-derived), `model`, `custom`, `effort` (`none | minimal | low | medium | high | xhigh | max`), `fast`, `thinking`.
- `choices` / `needs`: for each role × provider whether it may be assigned (`ok`, a human `reason` when not, `needsAck` for an `unverified` provider) and what each role requires (`build` for implementation / debugging / documentation, `research` for research).
- `toolModels[t]`: "Default model for each tool", `{ model: string | null, custom: boolean }`.
- `roleViews[r]`: view-only `{ tool, runsAs, who, status, notes }`. `runsAs` is the static command name plus **exactly** the model/effort arguments the stage will get (e.g. `claude --model sonnet --effort high`, `agent --model gpt-5.3-codex-high`, `codex exec --model=gpt-5.1-codex`), never a path. `status`: `ok | no-longer-available | list-unavailable | not-in-list | other-tool | signed-out`. `research.tool` is always `claude`.
- `rows`: the seven Settings rows, `{ id: ask|research|design|plan|review|build|verify, roles }` (the server never mirrors; the UI writes the same choice to every role of a row).
- `legacyNotices`: `{ tool, message }` per tool whose v5 `agents.<tool>.model` was not kept (static wording, **never the old value**), while that tool has no default chosen.
- `models[t]`: `{ effortLabel ("Effort" / "Model effort" / "Reasoning effort"), levels: {value,label}[], state, refreshing, fetchedAt, reason?, defaultLabel (what "Tool default (…)" names), customEffortHint, options: { value, label, efforts: string[] | null, hasBase, fast, thinking, noZdr }[] }`. Claude/Codex options are models (Claude's `default` alias is not listed — it is what "Tool default" means); Cursor options are families. Without a model service every `state` is `unavailable`. All labels are cleaned catalog text: render with `textContent`.

### `GET /api/runs/:key` → `ApiRunDetail`  (`404` if unknown)
Summary plus `notes[]` (the card's conversation: your notes and Conductor's), `plan`, `planMarkdown`, `planReview`, `verdicts[]` (per loop), `gates` (baseline + per-loop `GateRun` and `GateComparison`), `bugs[]`, `sessions[]` (each with a copyable `resumeCommand`), `timeline[]`, `diffStat`, `description`, `worktree`, `baseSha`, `commitSha`.
`graph` is `null` for a single-task run, otherwise `{ rev, final: 'pending'|'verifying'|'done', items[] }` with, per task, `id`, `key` (its subtask card), `title`, `role`, `objective`, `dependsOn[]`, `files[]`, `criteria[]`, `state` (`pending | ready | running | done | failed | blocked` — `ready` is derived: pending with every dependency done), `loop`/`loopBudget`, `commitSha`, `note` (capped). The run summaries (`ApiState.runs[]`, and the detail) carry `taskProgress` `{ total, done, running, failed, blocked }` when a graph exists.

### `GET /api/board` → `{ projects, items, milestones, research }` and `GET /api/items/:key` → `{ item, comments, children, decisions, graph, blockedBy }`
The raw board (newest 2000 items). Additive: an item made by "Design the work" also carries `design: { briefId, part, parts }` while its brief exists (parsed only from its strict `idemKey`); `research` is a **read-only projection** of the newest 50 research asks (`ResearchCardView`: lane `active | review | done | needs_you | canceled`, depth, opened/listed/unverified counts, `convertedTo`) — not board items, never journalled, no move/claim/edit; `blockedBy` lists the card's dependencies that are not Done yet (`{ key, lane }`, so a canceled dependency is visible). Cards with a run are driven through `/api/runs/:key/*`; these are for browsing. `graph` (same shape as in the run detail) is present on the card of a run that was split into tasks; its `children` include the Conductor-owned `subtask` cards. A move of such a card through `POST /api/items/:key/move` is refused with `409 managed` — retry or stop the work from the parent card.

### `GET /api/offline` → `{ online, checkedAt, operations[] }`
The connectivity probe's verdict (outbound HEAD to the providers' own hosts; a configured proxy or an undecidable probe counts as online) and which operations work offline (`offline-ok`: board, notes, history, project context, gates, settings) or need the network (`needs-network`, with the provider). A provider call that fails for network reasons pauses the run (`pauseReason: "offline"`, attempt refunded, backoff 30 s → 5 min, 24 h cumulative / 20-episode ceilings) and resumes when the probe says the network is back.

### Quick Ask (`POST /api/ask`, `GET /api/asks[/:id]`, `POST /api/asks/:id/{cancel,convert}`, `DELETE /api/asks/:id`)
`POST /api/ask { question (≤ 4000), repo?, allowChange?, follow? }` → `202` + the ask record (`running`); poll `GET /api/asks/:id`. The question is answered by ONE read-only call over a **snapshot** of the repo's base branch (committed regular files only; no `.git`, symlinks, submodules, agent configuration or uncommitted work; deleted afterwards); the answer states `branch @ sha` and the provider's isolation tier. Strict body (unknown fields, `createdBy`, `fastPath`, `autoStart` → `400`); limits `pipeline.asksPerHour` (default 20) and two at once → `429`; asks fail fast and are never queued or auto-retried. `allowChange: true` (ticked BEFORE asking) lets a `change` answer start the **fast path**: a work card by the server-only actor `user-ask` whose text is your own question; plan review is skipped only when the planner's own plan is small (S, ≤ 3 plain files, nothing protected); approval, holds and policies still apply and a build touching an unlisted file stops for you. `POST …/convert` makes a normal card by the server-only actor `ask-convert` (model text, untrusted ⇒ approval always forced; idempotent). The board schema is now version 2: an older build refuses it — no downgrade after Quick Ask is used.
**Follow-ups.** `follow` is the id of the earlier answered ask this question continues (quick asks only; `mode:'research'` rejects it). The server looks the earlier asks up in its own store (the client never sends history text): up to 4 earlier question/answer pairs of the same repository along the chain of `follow` ids, newest kept first, each capped (question 600, answer 2000, basis 200 characters; 8000 in total), redacted, and shown to the model as fenced untrusted data, one JSON object per line, to resolve references such as "it" or "that function". A malformed id is `400`. An id that is unusable as context (unknown, deleted, dismissed, not an answered quick ask, another repository) never fails the ask: it simply runs without history and the record's events say so. The record carries `follow` (only when earlier context was really used) and `historyCount` (how many pairs the model saw, 0-4); both are additive optional fields, so older versions simply ignore them.
**Online Ask and Code Research (`mode`).** `POST /api/ask` also accepts two more modes, each with its own strict body (any other field is a `400`):
- `{ question, mode: 'web-ask', follow? }` — **Online Ask**: a short answer from web pages. Web tools only, an empty scratch directory, **no repository text** (a repository is never accepted or defaulted). The record has `mode: 'web-ask'`, `basis: 'web (no repository access)'`, `result.answer` and `sources[]` (`url`, `title`, `quote`, `state`: `opened` = that exact URL was really fetched in the session, `listed` = it only appeared in search results, `unverified`; computed from the session's tool events, never from model text; unsafe URLs are dropped). It is routed like Research (Claude only), needs the network (`409 offline` otherwise), and **shares the hourly Ask budget** (`asksPerHour`, 1 per question) and its limit/pause/refund path. `follow` continues only an earlier `web-ask` of this kind (history lines carry `origin: web`).
- `{ question, mode: 'code-research', repo? }` — **Code Research**: a deeper, multi-step read-only investigation of the repository's snapshot (three times the normal read-only turn budget and wall clock, with ceilings of 150 turns and 60 minutes per attempt; worst case several attempts with the one corrective re-ask and provider fallback). The record has `codeReport { summary, findings[{ claim, status: 'verified'|'partial'|'unverified', evidence[{ file, lines, quote, state: 'verified'|'unverified' }] }], risks[], recommendation, steps[], limitations }`. **Conductor verifies every citation against the snapshot** before it removes it: the file must be a committed regular file that was materialised there (never a link, never outside it), `lines` is required (`N` or `N-M`), and the quote (12 to 300 characters) must occur inside those lines after whitespace normalisation; anything else is `unverified`. It counts as **3 of the hourly Ask budget**, only one runs at a time (`429 busy`), it needs one repository (the only registered one is the default), it never takes `follow`, and it cannot be turned into a task.
Records of these two modes are quarantined (not lost) by older versions that do not know the mode.

### "Design the work" and research briefs: `POST /api/briefs`, `GET /api/briefs[/:id]`, `POST /api/briefs/:id/{cancel,send}`, `DELETE /api/briefs/:id`, `POST /api/asks/:id/dismiss`
Feature detection: `GET /api/state` carries `home: { design: true, researchBrief, limits: { designPerHour, designUsed, researchPerDay, researchUsed } }` when the build has the service (else the endpoints answer `501 not_available`). Every body is strict (a plain object; any other key ⇒ `400`); ids are `^brf-[0-9a-f]{16}$` and are checked before any path is built (else `404`); every mutation needs the CSRF header like all others.
- `POST /api/briefs { kind: 'work' | 'research', line (≤ 4000), repo? }` → `202 BriefView` (`status: 'running'`); poll `GET /api/briefs/:id` (about once a second — brief saves do not emit an SSE event). The line is stored as one line (line breaks and repeated spaces collapsed), and that form is what the cards show. **work**: one read-only call (job *Design the work* = role `requirements`) over a snapshot of the base branch writes `{ title, summary, approach, files[{path, why, state: file|omitted|absent, protected, secretLike}], acceptance, risks, parts[≤ 8]{id P1…, title, summary, size, files, deps} }`; steps `scan → brief → parts`; one corrective re-ask on any schema or semantic error, then `failed` (never truncated into shape). **research**: the research brief is written **by Claude only, from your question only** (empty folder, no repository, no project facts) as `{ title, objective, questions, scope{in,out,timeWindow?}, sourceTypes, deliverable }`; a brief that introduces a web address, host or IP you did not type is rejected (URLs, `www.`, IPv4/IPv6 literals incl. `[::1]`, `0x7f000001`, `127.1`, private-range decimal forms, `localhost`, `.local`/`.internal`, cloud metadata hosts, `nip.io`-style names; plain public host names in prose are a documented residual). Errors: `400 choose_repo` (+ `repos`, work with several repos), `409 isolation`, `409 limited` (+ `retryAt`; nothing recorded, nothing counted), `429 limit` (names `designPerHour` — default 10/h, ceiling 30 — or `researchPerDay`, checked before a research brief is written), `429 busy` (two briefs at once), research only: `409 needs_claude` (Claude is not an eligible Context provider; nothing recorded or counted).
- `POST /api/briefs/:id/send` — **work** `{ parts: ['P1', …] }` (ids only; titles and text always come from the stored record) → `201 { briefId, keys, cards[{part, key, dependsOn}], plansStarting }`. Each selected part becomes a `work` card in To do authored by the server-only actor **`design`** (untrusted: its plan **always waits for your approval**, under every policy, on every re-plan). A dependency on a part you did not send is replaced by that part's own dependencies. The same selection again replays the result; another selection ⇒ `409 already_sent`; `409 bad_repo | archived | full` before anything is written; a failure part-way ⇒ `409 send_failed` (+ `cards` made so far), and sending the same selection again creates only the missing ones. A brief interrupted while sending is finished at the next start. **research** `{ depth: 'standard' | 'deep' }` → `202 { briefId, askId }` (a repeat ⇒ `200` with the same `askId`); starts the existing web-only Deep Research at once, never queued (`409 offline | isolation`, `429 limit | busy` return the brief to `ready`); Deep counts 2 against `researchPerDay`.
- `DELETE /api/briefs/:id` → `{ ok: true }` (`409 bad_state` while sending; a running brief is stopped first; cards already sent stay). `POST /api/briefs/:id/cancel {}` stops a running brief. `POST /api/asks/:id/dismiss {}` hides a finished research report from the projection's "Report ready" lane (research `done` only; idempotent).
- **No downgrade after the first use:** the board snapshot is stamped schema **3** (after a `pre-board-v3` backup in `~/.conductor-backups`) the first time this build opens it for writing; an older build then refuses the board. To go back, restore that backup (cards created since are lost).

### `GET /api/models` → `{ providers: CatalogView[] }`  (`501` when the build has no model service)
What each installed tool says it offers ("ask each tool, never assume"). Always three entries, in the order `claude`, `cursor`, `codex`. Each is a `CatalogView` (`src/models/types.ts`) and carries only these keys: `provider`, `state` (`reading` = first discovery running, no list yet · `fresh` · `stale` = a list is shown but the last refresh failed, or its saved time is impossible · `unavailable` = no list), `reason?` (one line, ≤ 200 characters: fixed wording plus redacted CLI detail, never an email or an absolute path), `refreshing?: true` (a refresh is running while a list is shown), and, when there is a list, `version: 1`, `account` (`"default"` for now), `source`, `cliVersion`, `fetchedAt?` (epoch ms; left out when the saved time is impossible), `signedIn` (`true`/`false`/`null`), `plan?` (Claude subscription name), and `models: ModelEntry[]`. A `ModelEntry` is `{ id, label, resolved?, efforts?, defaultEffort?, isDefault?, fast?, thinking?, adaptiveThinking?, thinkingOff?, noZdr? }`. `id` is exactly what the tool listed and passes that provider's id rule (`modelIdOk`): Claude ids may carry one `[a-z0-9]{1,8}` suffix (e.g. a `[1m]` context variant); Cursor and Codex ids never have brackets. Cursor also has `families: { family, efforts, thinking, fast, label, noZdr, ids }[]`, recomputed from the list and never stored. In `efforts`, `""` means the base id. The account email and organisation are never stored, logged or served. **Codex is always `unavailable`** ("Codex model discovery is not available yet"): nothing about Codex is looked up until its own Security gate. Reading never starts a discovery and never waits for one.

### `GET /api/runs/:key/log?after=<seq>&limit=<n>` → `{ events: LogEvent[], next: number }`
Backlog for the live log. `after` default 0, `limit` default 500 (max 2000). `next` = highest seq returned (pass as `after` next time).

### `GET /api/events` — Server-Sent Events
`text/event-stream`, `retry: 3000`. Events (JSON `data`):

| event | data | when |
| --- | --- | --- |
| `state` | `{ now, runs, cards, engine, quota, waiting?, accounts? }` | any run/engine change (debounced ≤ 1/s) — **merge into local state** (`waiting` / `accounts` when present) |
| `log` | `{ key: string, event: LogEvent }` | each normalised agent event (both Claude and Cursor) |
| `toast` | `{ level: 'info'\|'warn'\|'error', text: string }` | notable moments (needs human, limit pause, ready) |
| `ping` | `{ now }` | every 20 s (keep-alive; use to detect a dead stream) |

On reconnect the UI should refetch `GET /api/state` and the open run's `GET …/log?after=<lastSeq>`.

## Mutation endpoints (all return `{ "ok": true, … }` on success)

| Endpoint | Body | Result / notes |
| --- | --- | --- |
| `POST /api/tasks` | `{ title: string, description?: string, repo?: string }` | `201 { ok, key, url:'' }` — creates a card in To do (the engine starts it right away). `repo` must be a registered repo name (optional if only one). Extra fields (`author`, `kind`, `lane`, `key`, …) are ignored: authorship is server-side. |
| `POST /api/projects` | `{ key: 'ABC', name: string, repo?: string }` | `201 { ok, project }` |
| `POST /api/items/:key/move` | `{ lane: 'backlog'\|'todo'\|'done'\|'canceled' }` | the only way to move a card; cards with a run are routed through the engine (park / restart / finish / abort); `active`, `needs_you`, `review` are refused (`400`) |
| `POST /api/items/:key/comment` | `{ body: string }` | adds YOUR note (author is always `user`); read by the next plan |
| `POST /api/items/:key/edit` | `{ title?, description? }` | `null`/absent leaves a field unchanged; a description edit on a card with a run halts it at the next stage boundary |
| `POST /api/runs/:key/approve` | `{ rev: number }` | approve a plan in `awaiting_approval`; **`rev` is required** and must be the current plan revision (`409` if the plan was replaced) |
| `POST /api/runs/:key/retry` | — | retry the origin stage of a `needs_human`/`failed` run, or re-run from plan when `ready` (rework) |
| `POST /api/runs/:key/resume` | — | resume a `paused` run now (a `parked` run is restarted with `move → todo`) |
| `POST /api/runs/:key/abort` | — | kill the running agent (process group) and mark `aborted` |
| `POST /api/runs/:key/cleanup` | — | remove the worktree (and local branch if merged) of a `ready`/`finished`/`aborted` run |
| `POST /api/runs/:key/open` | `{ target }` | `target`: `cursor` (open worktree in Cursor), `terminal-claude` / `terminal-cursor` (new Terminal window resuming the latest session of that agent), `claude-desktop` (`claude --desktop --resume <id>`), `finder`. Server computes all paths/ids from the run record. |
| `POST /api/engine/pause` | `{ paused: boolean }` | global pause/resume (no new claims; running stages finish) |
| `PUT /api/run-mode` | `{ runMode: 'per-settings' \| 'complete-auto', confirm?: boolean }` | The **only** writer of the run mode. Strict: a plain object whose only own keys are `runMode` and `confirm` (anything else, `__proto__`, `constructor`, a bad value or a non-boolean `confirm` ⇒ `400`). Turning Complete auto **on** needs `"confirm": true` (`400 confirm_required` with a static text naming what still waits); turning it off does not. Same mode ⇒ `{ ok, runMode, changed: false, waiting }` and nothing is written. A change writes only `pipeline.runMode` (+ `runModeChangedAt`), persists first and only then switches memory: a refused save ⇒ `500 save_failed` and the mode is unchanged everywhere. Returns `{ ok, runMode, changed: true, waiting: { total, bulkApprovable, eligible: [{ key, rev, title }] }, settings }`; SSE `state.engine.runMode` follows. Plans already waiting are **never** approved by the switch |
| `POST /api/runs/approve-waiting` | `{ runs: [{ key, rev }] (1–50, unique), confirm: true }` | "Approve waiting plans": a bulk **human** approval of exactly the listed runs (the server never expands "all"). Strict body; missing `confirm` ⇒ `400 confirm_required`. Per run, fail closed: `missing`, `not_waiting`, `stale` (rev), `forced` (a forced hold — a run held before run modes existed counts as forced —, an untrusted source, or a card authored by a tainted actor such as `design`), `risky` (keeps the per-card confirmation). Returns `200 { approved: string[], skipped: [{ key, reason }] }`; partial success is normal |
| `GET /api/accounts` | — | `{ accounts: AccountView[], limitRule, limitRuleEffective }`. `AccountView` is an allow-list: `provider, id, name, order, isDefault, status ('ready'\|'in-use'\|'at-limit'\|'not-signed-in'\|'not-installed'\|'checking'\|'unknown'\|'unavailable'), until?, untilKind?, plan?, usage? (clamped), checkedAt?, inUse, buildReady? (Cursor), signInCommand, note?` — never a path, an email or a secret. Also in `GET /api/state` (`accounts`) and SSE `state` |
| `POST /api/accounts` | `{ provider: 'claude'\|'cursor', name }` | `201 { account, signInCommand }` — metadata + an EMPTY 0700 folder, no CLI runs (a zero-quota check follows in the background). `400`: unknown key, non-object, `__proto__`, bad provider, `codex`, empty / > 40 / email-shaped name, any key/token/password/credential field. `409`: duplicate name per tool, more than 8 accounts |
| `PUT /api/accounts/order` | `{ provider, ids }` | an exact permutation of that tool's ids, else `400` |
| `PUT /api/accounts/:id` | `{ name }` (for `default` also `provider`) | rename (label only) |
| `POST /api/accounts/:id/check` | `{}` | `202 { account }` within 10 s (per-account discovery, zero quota) |
| `DELETE /api/accounts/:id` | — | `default` ⇒ `409`. Stops and restarts any stage on it, aborts its asks/briefs, signs out (`claude auth logout` / `agent logout`, 20 s), deletes the folder and the model cache: `{ removed, id, signedOut, restarted, note? }` |
| `PUT /api/settings` | partial `Settings` | validated server-side; returns `{ ok, settings }`. `limitRule ∈ { switch, same, wait }` (anything else ⇒ `400`; `limitRuleEffective` is read-only); `settings` carries both. Under same/wait, `onClaudeLimit` still edits the chains (it then affects only non-limit fallbacks). A `runMode` / `runModeChangedAt` key ⇒ `400` ("Change the run mode with PUT /api/run-mode"). `stages` / `onClaudeLimit` are **derived** from the role chains; a PUT changes only the first claude/cursor slot (or the cursor-follows-claude rule) and leaves every other chain entry alone |
| `PUT /api/roles` | `{ roles?: { <role>: { providers: ProviderId[1..4], autoByComplexity?, tool?, model?, custom?, effort?, fast?, thinking? } }, toolModels?: { <tool>: { model: string \| null, custom?: boolean } \| null }, acknowledge?: ProviderId[] }` | strict: any other top-level or entry key ⇒ `400`; plain objects only; role/tool names own-property checked; provider ids from the registry; every new pairing is checked against the capability/tier gate (`400 unsupported_pairing`); an `unverified` provider needs `acknowledge` (`409 needs_acknowledgement`); a `blocked` one is refused. **Absent key ⇒ keep, `null`/`false` ⇒ clear** (except `providers`, which is required). Model choices are judged against the role's new head tool and its current model list: `400 unknown_model`, `models_unavailable` ("refresh models, choose Tool default or type a custom id"), `effort_not_offered`, `not_offered` (Fast/Thinking), `tool_mismatch`; every refusal carries `error.field`. An entry whose head and model fields are unchanged is not re-judged (a GET→PUT round trip always works). A head change that echoes the old model fields clears them (with a notice) and fits the effort to the new tool's default; a model change without `effort` fits the stored effort. Nothing is saved on any 4xx. Returns `{ ok, roles, toolModels, roleViews, notices }` |
| `POST /api/roles/preview` | same body as `PUT /api/roles` | **Never saves**: (no backup, no model refresh, no spawn). Returns `{ roles, toolModels, roleViews, notices, problems: { field, code, message }[] }` with the draft fitted (efforts/flags/variants) and its `runsAs`; pairing and semantic refusals come back as `problems` with `200`; only a malformed body is `400`. Same CSRF and body cap as every mutation |
| `POST /api/providers/:id/test` | `{ level?: "cheap" \| "canary", confirm?: true }` | `:id` is checked against the registry first (`404`). `cheap` (default) is a zero-quota look (version / login status). `canary` calls the model: it needs `"confirm": true` **on every call** (`400 confirm_required`), runs one at a time per provider (`409 busy`), is refused while stages are running, and has a one-minute cool-down (`429 cooldown`) |
| `POST /api/auth/logout` | — | clears the session cookie |
| `POST /api/models/refresh` | `{}` or `{ provider: "claude" \| "cursor" \| "codex" }` | `202 { providers: CatalogView[] }` at once, while the refresh runs in the background; poll `GET /api/models` while any entry has `refreshing: true` or `state: "reading"` (no SSE event exists for this). Strict: the body must be a plain object whose only own key may be `provider`, and it must be a registry id. Anything else (an array, a scalar, an unknown key, `__proto__`, `constructor`, an unknown provider) ⇒ `400`. An empty body refreshes every provider. A second refresh of the same provider inside 10 s returns the cached view (still `202`, no new spawn). Discovery is zero quota: Claude gets one `initialize` control request and no prompt, Cursor runs `agent --list-models`. One discovery runs at a time, and each is bounded by 15 s (≈ 21 s worst case including the kill grace) and 2 MB of output. A failure keeps the last list (`stale`, reason "showing the list from HH:MM — …"). |

### Setup endpoints (used by the wizard; idempotent)

Storage failures answer `503`; validation failures `400`; unknown keys `404`; refused moves/duplicates `409`.

| Endpoint | Body | Result |
| --- | --- | --- |
| `POST /api/setup/repo` | `{ path: string, name?: string }` | validates it is a git work tree (not `/`, not `$HOME`), detects base branch + gates: `{ ok, repo: ApiRepo }` |
| `DELETE /api/setup/repo/:name` | — | unregister (does not touch the folder) |

## UI behaviour requirements (for the implementer)

1. **First load**: `GET /api/state`. If `!setup.complete`, render the **Setup wizard** (2 steps: Agents → Repository) with per-step status from `setup.steps`. Otherwise render **Home** (`#/`), the default view.
   - **Home** has one composer (Auto / Ask / Build / Research), a repo chip and a "Handled by" chip, with the conversation below it. Requests go to:
     - Ask → `POST /api/ask`, then poll `GET /api/asks/:id`;
     - Research → `POST /api/ask {mode:'research'}`, then poll the same way;
     - Build → `POST /api/tasks`.
   - Asks fail fast. The server's message is shown verbatim and nothing retries automatically.
   - `GET /api/roles` provides the "who" wording. Choosing a tool changes a **global** setting, through `PUT /api/roles`, which works as follows:
     - the role's whole entry from a fresh GET is sent back, with only `providers` changed;
     - an `unverified` provider needs one explicit confirmation, and `acknowledge` lists exactly the confirmed ids;
     - `notices` are shown.
   - Settings no longer sends `stages`.
2. **Dashboard**: header (Home / Board tabs, engine pill with pause/resume, Claude quota meter from `quota.claude.utilization7d` + reset time, "New task" button on the Board, settings), **board** (`#/board`) with columns **Backlog** and **To do** (run-less `cards`, with Start / Park / Cancel) followed by the run columns from `ApiRunSummary.column` (`queued, planning, plan_ready, building, verifying, needs_human, paused, ready`; `closed` runs live in a collapsible "History"). Cards show key, title, repo, activity sentence, loop `n/max`, open-bug count, an `unverified` badge, who is working (Claude/Cursor chip).
3. **Run detail** (drawer on desktop, full page on phone): tabs **Overview** (activity, next action, needs-human reason, action buttons honouring `canApprove/canRetry/canAbort/canCleanup/canPark/canFinish`), a **Notes** panel (the card's conversation + an input for your notes), **Live log** (SSE; filters by agent; auto-scroll with a "pinned" toggle; collapse noisy tool events), **Plan** (rendered `planMarkdown` + AC), **Verification** (verdict per loop, gate table with baseline vs now, bugs with severity), **Sessions** (resume commands with copy buttons + "Open in Claude app / Cursor / Terminal" buttons), **Timeline**.
4. **Honest empty/limit states**: when `engine.providerPause.claude` is set show a banner "Claude usage limit — resuming automatically at <time>"; when health warns about leaked instruction files, show them; `setup.complete:false` never shows an empty board.
5. **Accessibility/responsive**: keyboard reachable, focus-visible, ARIA live region for toasts, `prefers-color-scheme` light/dark (and respects `prefers-reduced-motion`), works at 390 px width without horizontal page scroll.
6. Never render server strings as HTML (`textContent` only); no `innerHTML` with data.

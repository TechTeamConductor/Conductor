**Board (M1a).** Fresh, persisted, versioned (not derived from `FakeLinear`).
```
Project  {id, key[A-Z]{2,6}, name, repo (registered repo name), nextSeq, createdAt, archived?}
WorkItem {id, key=<PROJECT>-<n>, projectId, parentId|null, dependsOn[], milestoneId?, kind: work|ask|research|subtask|bug,

Comment  {id, itemId, author: user|conductor, body, ts, idemKey?}
Decision {id, projectId, itemId?, title, body, author, ts}      // project-level decisions & milestones (V3)
```
Storage: `<CONDUCTOR_HOME>/board/{snapshot.json, journal.ndjson}`; every mutation appends one NDJSON line of the **resulting entity** (`{t:'item'|'comment'|'project'|'decision'|'del', v}`) with a monotonically increasing `seq`; snapshot compaction (atomic temp+rename, then new journal) every 500 ops and on clean shutdown; load = snapshot + replay journal entries with `seq > snapshot.seq`, a torn final line is ignored and reported. Idempotency: `comment(…, {idemKey})` and `create(…, {idemKey})` are no-ops returning the existing entity when the key is already present (index rebuilt on load).

**Persistence invariants (Reviewer condition C2 — written down, each with a test):** (1) creating an item is **one** journal line containing the item *and* the project's bumped `nextSeq` (and `nextSeq` is additionally re-derived as `max(key suffix)+1` on load), so a torn write can never re-issue a key; (2) a corrupt **last** line is ignored and reported; a corrupt **middle** line makes the board refuse to open (clear error, nothing written) — never skipped silently; (3) durability: every journal append is `write`+`fsync`; snapshots are written to a temp file, fsynced, renamed, and the directory is fsynced — so *acknowledged operations survive both a process crash and power loss*; (4) files are 0600, dirs 0700 (like `RunStore`); (5) single writer: a second **writing** open of the same board refuses (lock), while a **read-only open mode** (C3) takes no lock and never writes/compacts — used by `doctor`, `migrate --dry-run` and diagnostics so they work while the app runs; (6) **server-side authorship (C4)**: `author`, `createdBy`, `kind`, `lane` are set by trusted server code only (the HTTP handlers pass constants); request bodies can never carry them, so a client cannot forge `author:'conductor'` and break the user-intent-vs-Conductor-output split that replaces `isConductorComment`. Keys: `PROJECT-n` satisfy both `KEY_RE`s and branch naming; the importer preserves existing keys (e.g. `BAR-363`) and sets `nextSeq = max+1`. All Conductor-authored titles/bodies are redacted + neutralised before they enter the board (H3 survives).

**Versioning framework (M1a).** `src/schema/`: `readVersioned(file, {kind, current, migrations})` — missing version = 1; **newer than known ⇒ throws `NewerVersionError` and nothing is written (runtime refuses to start with a clear message)**; older ⇒ ordered migrations in memory, and **before the first write of a migrated file a timestamped backup is taken** (single backup root **`~/.conductor-backups/<ts>/`** outside every home, overridable with `CONDUCTOR_BACKUP_DIR`; **the test harness and every test that can trigger a backup must set it to a temp dir** so tests can never write to the user's real backup directory; sha256 manifest). Unknown keys are preserved on save (`config.extra`). **One story for versions:** M1a stamps `schemaVersion: 1` on `state.json`, `run.json` and the board (snapshot header `schemaVersion` + a `v` field on every journal line) and treats a *missing* stamp as 1, so v1-shaped files are current at M1a; `config.json` keeps its own `version` field at 2; **M1b** raises `run.json` current to 2 together with its migration; **M1c** registers config v3. The fsync/durability claim is scoped to the **board only** (`RunStore` uses `atomicWriteFile` without fsync) — it is not a whole-system power-loss guarantee.

### Lane ownership, human commands, projection and crash protocol (round-2 blocker 3)

**Ownership rule.** Humans (HTTP API) may set only `backlog`, `todo`, `done`, `canceled`; **Conductor owns `active`, `needs_you`, `review`** (Conductor also *projects* `backlog/done/canceled` for parked/finished/aborted runs after the run record changed). The property that matters: **the engine never reacts to a lane change it did not command**, so *no diffing of board lanes is needed to infer human intent* and `run.expected.column` is not used for that (it is dropped). Human intent arrives only as **commands** (`PATCH /api/items/:key {lane}`, approve, retry, comment, abort) handled in one place (`engine.applyHumanMove` etc.); the engine never reacts to board lane changes it did not command. The engine's remaining board input is the **claim scan**: `claimable()` = items with `lane==='todo'`, `parentId===null` (v1 skipped children of *any* Conductor run — a child is never claimable), `autoStart`, `kind` ∈ work/ask/research, and **no run yet** (`store.has(key)` false).

**Desired-lane table (run → lane, level-triggered).** none→`todo` (human-owned); `queued|running|paused|failed`→`active`; `awaiting_approval|needs_human`→`needs_you`; `ready`→`review`; `finished`→`done`; `aborted`→`canceled`; `parked`→`backlog`. `item.stage` carries the fine-grained label (planning, plan_review, awaiting_approval, building, verifying, …) for the UI.

**Human command matrix (run.status × command → effect).** `retry` = `rerunFromHuman` (5/hour limit, backup ref before any reset, fresh `agentRuns` budget; stage-level when `needs_human` with a build/verify/plan_review origin — v1 semantics unchanged).

**Write order and crash protocol (replaces "startup reconcile heals drift").** Everything is synchronous in one process; no `await` sits between the two writes of a pair.
1. **Run store first, board second.** A command or stage transition records its effect in `run.json` (status/next/expected intent **and a pending effect record**), then applies it to the board. The pending record is kept (v1's mechanism, minus the remote parts): `Effects` writes `{kind, payload, status:'pending'}` to `run.effects[effKey]` **before** the board call, applies it with the idempotency key `<RUN>:<effKey>`, marks it `done`; `flush()` (already called per run each tick and now also once at startup for **every** non-terminal *and recently-terminal* run) re-applies anything still `pending`. A crash at any point therefore converges: before the board write → flush applies it; after the board write but before `done` → flush re-applies, the idempotency key makes it a no-op. Attempt counters / give-up / marker lookups are deleted (a local write cannot half-fail across a network).
2. **Level-triggered lane projection.** At startup and every tick, for each run compare `desiredLane(run)` with `item.lane`; if different and no state effect is pending, enqueue one. This heals drift even if a pending record was lost (e.g. run.json says `ready` but the card is stuck in `active`; `needs_human` explanation missing is covered by its pending comment effect).
3. **Bug children:** `board.create({kind:'bug', parentId, idemKey})` happens inside the effect; `BugRec.itemKey` is set by the effect's completion handler **and** re-derived on load by looking up children by idemKey, so a crash between child creation and the `BugRec` update converges without `decide()` re-running.
4. **Orphans:** run without item ⇒ status `aborted`, files kept, one event; item in `active/needs_you/review` without a run ⇒ lane reset to `todo` only if the item is claimable-shaped, else flagged on the dashboard.
5. **Crash-injection tests, one per window:** (a) after run.json write, before board write; (b) after board write, before effect marked done; (c) bug child created, `BugRec` not updated; (d) claim: run created, lane still `todo`; (e) human `done`/`canceled`/`backlog` command: run updated, lane not yet; (f) journal torn last line; (g) journal corrupt middle line (refuse to open). Each uses the existing kill-after-N-ops harness (child process + `process.exit` hook / `SIGKILL`).

**`integrity()` keeps the v1 semantics (round-2 blocker 2):** the approved plan and acceptance criteria were written against the description text, and the builder reads a `run.description` snapshot, so **a description edited mid-run halts the run at the next stage boundary** (`needs_human`, reason "description changed", test unchanged) and a restart re-plans (rev+1, new `descHash`). Title edits are re-read at restart. There is no attribution check (single user); the board only supplies the item and its description hash. (An earlier draft said user edits are "picked up" silently — **withdrawn**.)

## 5. Testing Strategy

- **Board (unit):** CRUD + invariants (no cycle in `dependsOn`/`parentId`, key uniqueness across projects, `nextSeq` monotonic); journal replay equals live state (property test over random op sequences); torn last line; kill -9 mid-append (child process killed, reopened, state consistent); snapshot compaction crash-safety (temp file left behind is ignored); idempotency keys survive reload; redaction of Conductor-authored text; 1 MB comment bodies; 10 k items load time bound.
- **Schema:** each migration step; real-shaped v1 `config.json` fixture → v3 with unknown keys preserved; newer version refused with nothing written; corrupt JSON → backup + safe start; backup taken exactly once before first write; run.json v1 → v2 field moves exactly as the mapping lists.
- **Engine on board (fake CLIs, real git):** every migrated test per matrix; new: the **human command matrix as a table-driven test** (every cell of run.status × command, including the 409s); approve rejected outside `awaiting_approval` or for an old `rev`; restart-rate-limit; board change wakes the engine; a client cannot set `author`/`createdBy`/`kind`/`lane`∉{backlog,todo,done,canceled} (C4); level-triggered projection heals a deliberately drifted lane; the **seven crash-injection tests (a)–(g)**; idempotent comment/child on crash-replay; the `integrity()` description-edit test unchanged (halt at stage boundary → re-plan on retry).
- **Importer / migrate (side-by-side):** dry-run writes nothing anywhere; apply on a synthetic BAR-363-shaped home; the v1 home is **byte-identical before/after** (sha256 manifest); crash injected between stage-built / validated / renamed leaves either no v2 home or a complete one; refuses to overwrite an existing v2 home; runs while a v1 instance holds its lock (read-only open); `assignedPickup` runs flagged untrusted → plan approval forced; hostile imported keys rejected by `KEY_RE`; imported in-flight runs never reuse v1's worktree/branch.

## 6. Risks and Dependencies

- **Big-bang inside M1b** (types change everywhere). Mitigation: harness rewritten first; matrix is the checklist; v1 tag + backup + isolated clone; M1a lands independently.
- **Losing a v1 safety property when retiring tests.** Mitigation: matrix lists survivors with identical assertions; Reviewer checks the diff of retired test names against the matrix.
- **Journal correctness** (the new persistence layer). Mitigation: property test + kill -9 test; snapshot is atomic; single-writer (lock) assumed — a second process opening the board refuses (reuses `lock.ts`).
- **User's live data**: never written. `conductor migrate` only *reads* the v1 home (side-by-side), after a dry-run, with a backup copy outside both homes. The live v1 instance keeps running untouched; it can never be corrupted by v2 code or migrated data. Landing the v2 clone into the original repo is a separate, user-initiated local fast-forward after the user stops the live instance (no push/PR).
- **Run-store ↔ board consistency** (two files). Mitigation: board is the human-facing ledger, run store is execution state; every cross-write uses idempotency keys so replay after a crash converges; drift is healed by the **crash protocol** above (pending records + `flush` + level-triggered lane projection) — never by auto-resetting an orphaned item to `todo` (K4).
- **Assumptions:** single local user; JSON + journal is enough (SQLite decision recorded in master); keys `PROJECT-n`; dashboard is the only writer besides Conductor.
- **Not in M1:** hierarchy execution, dependencies *execution* (fields exist, executed in M3), provider roles (M2), context (M4).

## 2. Expected State

**Three ways in. Quick Ask answers small questions (and performs focused, simple changes through a fast path) with minimal overhead; Deep Research gathers online evidence under a hardened, fail-closed profile and produces a cited, honest report that can be turned into planned work; Engineering Work is unchanged.**

### 2.1 One shared agent caller

`src/agents/caller.ts` extracts the provider-call loop of `callReadOnly` into a **run-independent** `callAgent({ role, stage, prompt, schema, cwd, validate, signal, secrets, budget, onEvent, hooks })` returning a discriminated result (`ok | paused(limit|offline) | aborted | failed(reason)`): schema validation + one corrective re-ask, max-turns retry, router + chain advance, limit/offline classification, redaction, events, quota recording. `stages.callReadOnly` becomes a thin adapter that translates the result into run transitions (**behaviour byte-for-byte**: every existing engine-plan/limit/safety/loop/regress test passes unchanged — extraction gate, characterization first as in M2). Asks and Research use the same function.

### 2.2 Persistence (`<v2 home>/asks/`)

`AskRecord { id, mode: 'quick'|'research', repo?, question (≤ 4000), createdAt, updatedAt, status: 'running'|'paused'|'done'|'failed'|'canceled', provider?, sessionId?, result?, error?, events[] (≤ 200 lines, redacted), tokens/cost?, convertedTo?: itemKey }` — one JSON file per ask (0600, dir 0700, `ensureRealDir`, durable atomic write, versioned via `loadVersioned`), `index.json` capped at 500 entries (oldest pruned), ids `ask-<hex>`; every id validated before a path is built. Results are **untrusted data**: rendered as text/markdown through the existing sanitising renderer, never executed, never fed to builder prompts, fenced when shown to any provider.

### 2.3 Mode A — Quick Ask

- **Input:** `POST /api/ask { question, repo? }` (repo optional: with one registered repo it defaults; with none it is a general question).
- **Context:** the M4 pack (deterministic facts + the modules that match the question) + the question — "retrieve only the relevant project context".
- **Where it runs — a read-only SNAPSHOT, not the user's checkout (deliberate, safer than the master text):** built by **Conductor's own extractor** (§2b-1, not `git archive | tar`) from the repo's `baseBranch` commit into a 0700 scratch directory (regular files only, no `.git`, no hooks, no config, no untracked or uncommitted files — so no `.env`, agent-config directories omitted), deleted afterwards; over the caps → "too large for Quick Ask — use Engineering Work". The answer is stated to be based on *branch @ sha*. Provider profile = the existing read-only profile of the router's choice for the `context` role (Claude's fail-closed predicate; Cursor `ask`; Codex read-only sandbox), with the UI stating the tier ("answered by Cursor in ask mode — weaker isolation").
- **One call**, schema `ASK_SCHEMA { kind: 'answer'|'change', answer?: markdown (≤ 20 000), change?: { title, description, files[], complexity: 'S'|'M'|'L' } , citations?: [{file, lines}] }`. The model decides whether the request is a question or a request to change something.
  - `answer` ⇒ stored and shown; no card, no worktree, no branch.
  - `change` ⇒ **offered** by default: the answer shows "Let Conductor make this change" as a button. **Execution is the user's choice per ask:** a visible, default-off "let Conductor make this change if it is small" option (`allowChange: true`); only then may the **fast path** start (rules in §2b-2). The fast path creates a normal work card whose **description is the user's own question** (never the model's `change.description`), skips plan review **only**, and every approval/hold the configured policy or the plan requires still applies.
- **Escalation:** "Turn into work" on any ask creates a normal card (title from the question, description = the question + the answer as an *untrusted, fenced* note) created by the server-only actor `ask-convert` ⇒ the card is `untrusted` (approval forced under every policy, §2b-3).

### 2.4 Mode C — Deep Research (hardened; the part that needs Security design sign-off)

- **Who may do it:** the `research` role, gated by `webResearchIsolated` — **derived** (a provider exposes `runResearch` AND its research profile's fail-closed predicate is baselined in code); today only Claude. Codex (`--search` exists, isolation unproven) and Cursor are **not** eligible; the router refuses them with the reason (`ROLE_NEEDS.research` already requires it).
- **Claude research profile** (`buildClaudeArgs('research')`) = the existing read-only argv (`--permission-mode dontAsk`, `--permission-prompts none`, the credential `--disallowedTools` list, `--strict-mcp-config`, `--disable-slash-commands`, `--safe-mode`, `--max-turns` capped) with **exactly** the deltas of §2b-4. **Default (non-repo-aware) research has NO file tools: `--tools WebSearch,WebFetch` only** (init set exactly `{WebSearch, WebFetch, StructuredOutput}`); `Read, Grep, Glob` are added **only** for the explicit repo-aware opt-in (init set `{Glob, Grep, Read, StructuredOutput, WebFetch, WebSearch}`) — Read plus WebFetch is a data-plus-exfiltration pair and the default must not have it. No Bash, Edit, Write or MCP in any profile. `checkClaudeInit(init, {profile})` is profile-aware and fail-closed; any other tool ⇒ isolation violation ⇒ the run stops (`errorKind:'isolation'`, never falls back). **Negative test per profile:** the plan/review/verify profile still **rejects** `WebSearch/WebFetch` in its init; the research profile rejects `Bash`/`Edit`/`Write`/an MCP server.
- **A verified permission fact is required before implementation (§2b-4 defines the contract):** `--permission-mode dontAsk` denies anything not pre-allowed and WebSearch/WebFetch are ask-by-default tools, so the probable result is that they are denied. The plan therefore **pre-approves exactly one mechanism**: `--allowedTools` entries that are bare `WebSearch` and `WebFetch` (nothing else). The first implementation step is the opt-in live probe `doctor --research-probe --yes` (spends quota, records an add-only version-bound record); if the profile cannot work within that mechanism, **M5-research stops and is reported not delivered** — nothing is widened.
- **Where it runs:** default cwd = **an empty scratch directory** and the default prompt is **the user's question only** (no M4 pack: module/script/file names in a prompt could be put into a fetched URL). **Repo-aware research is an explicit per-task opt-in** (`repoAware: true`, shown in the UI with: "the agent can read the repository snapshot and could include its content in web requests"): then — and only then — cwd = the §2b-1 snapshot, the file tools are enabled, and the deterministic M4 facts (never summaries/history digests) are added to the prompt; the credential deny-list stays.
- **Citation integrity is structural but limited (§2b-5):** the session's structured tool events are folded into `observedUrls` (WebFetch `tool_use` inputs → class `read`; URLs in the structured WebSearch result → class `listed`); never URLs found inside fetched page content or model text. `RESEARCH_SCHEMA { question, summary, findings[{claim, evidence, confidence: high|medium|low, sources: [{url, title, quote ≤ 300}]}], alternatives[{name, pros[], cons[]}], recommendations[], unverified[], openQuestions[] }`. Conductor — not the model — computes each finding's status: **`verified` = at least one source that was `read`**; otherwise it is moved to `unverified` (a `listed`-only source is shown as "listed, not opened"). **What "verified" means: "a cited URL was actually opened in this session" — it does NOT mean the page supports the claim, and `quote` is labelled "model-reported, not checked against the page".** No independent fact-checking is claimed; that sentence appears next to every report.
- **Rendering:** the report is `<untrusted>` data: prose is rendered with links **non-clickable**; only the structured `sources[].url` (normalised, https/http allow-listed) are clickable, opened with `target=_blank rel="noopener noreferrer"`; never executed; `javascript:`/`data:` rejected at the API boundary (details §2b-9).
- **Convert to plan:** "Turn into an engineering plan" creates a work card through the server-only actor `research` (§2b-3 gives `untrusted` a real mechanism), so plan approval is forced **regardless of policy**; description = the user's question + the recommendations as a fenced untrusted block.
- **Offline / pause for asks (Reviewer M5-5):** research needs the network (`needs-network (Claude)` in `/api/offline`); refusal only when the probe says `offline` (not `unknown`). An ask has no run to wait in: **an interactive ask fails fast** with "usage limit until <time> — try again" / "offline — try again" and **no queued retry**; a running ask at shutdown is marked `failed: interrupted` with its scratch deleted and is **never re-run automatically**.
- **Abuse limits:** `pipeline.asksPerHour` (default 20), `pipeline.researchPerDay` (default 5, ceiling 20), one running research at a time per provider; each counts as agent-run budget of a system "ask" bucket.

### 2b. Review conditions — BINDING (Security `workspace-v2-m5-m7-security-design.md` M5-1…M5-16; Reviewer M5-1…M5-5)

**Decisions taken by the Lead on the Security questions (recorded, the user may override):** D10 a source that was only *listed* does **not** make a finding verified (shown as "listed, not opened"); D11 research is offered **only with a passing per-CLI-version probe record**; D12 agent-config directories are **omitted** from the Quick Ask snapshot; D13 the research SSRF/local-service residual is accepted **only with §2b-6 (a)–(d) in place**.

1. **Snapshot construction (M5-1).** Built by Conductor code, **not** `git archive | tar`: read `git ls-tree -r -z --long <40-hex commit>` plus `git cat-file --batch` (or parse the `git archive --format=tar` byte stream with a Conductor-owned reader). Only **regular files** are written (`O_CREAT|O_EXCL|O_NOFOLLOW`, files 0600, dirs 0700); symlinks (120000), gitlinks (160000), hardlinks, devices and fifos are not materialised and the answer says "N symlinks omitted". Entry names validated: no `..`/`.`/empty segment, not absolute, no control characters, no `.git` segment (case-insensitive), length ≤ 1024, depth ≤ 64. **Agent-config set omitted** (`.claude/`, `.cursor/`, `.codex/`, `.agents/`, `.husky/`, `.mcp.json`; the UI says "agent configuration omitted"; markdown instruction files stay — the same residual as Engineering read-only stages). Caps measured **before** writing from the `ls-tree --long` sizes: total ≤ 500 MB, files ≤ 200 000, one blob ≤ 25 MB (larger skipped and counted); over the total cap → refused "too large for Quick Ask". The commit is resolved once to a 40-hex id (`rev-parse --verify --end-of-options refs/heads/<branch>^{commit}`) and only that id is passed on; every git call uses the hardened env (`GIT_CONFIG_GLOBAL` null device, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, **`GIT_NO_LAZY_FETCH=1`**, `--` before paths). The UI states the answer reflects the committed base branch (`branch @ sha`), not the working tree, and that `export-ignore` files may be missing. **AC2 test:** a symlink to a canary file outside the snapshot is unreachable by `readFileSync` through the snapshot path and by the fake agent's Read.
2. **Fast path trust rules (M5-2).** (a) Only when the request carried `allowChange: true` (UI checkbox, default off, own-property boolean); otherwise a `change` is only offered. (b) It skips plan **review** only; approval goes through the **single approval decision** (today `approvalGate`, M6 `decideApproval`): `planApproval: manual|first`, `L`, protected paths, `untrusted`, M6 policies and risk rules all still hold — it never auto-approves over a policy that says hold (precedence: a policy can only add holds, the fast path never removes one; M6-6). (c) Eligibility is decided on **the planner's plan** (`complexity === 'S'`, `filesToChange` without protected, secret-looking or `.git*` paths, ≤ 3 files, relative and normalised), **not** on `ASK_SCHEMA.change`; if the plan disagrees with the ask's claim the run takes the normal approval path. (d) The builder's task text is the **user's literal question** (fenced as task) plus the planner's plan; the ask model's `change.description`/`files` are not forwarded. (e) Because plan review is skipped, the post-build scope check on a fast-path run is **diff ⊆ plan files for ALL paths**; a violation ends `needs_human`. (f) `Run.fastPath`, `createdBy:'user-ask'` and `autoStart` are assigned only by server code; the card create/edit/import HTTP schemas reject or strip them (tested per field). (g) Limits: fast-path starts ≤ 5 per hour (ceiling 20), ≤ 1 running fast-path run per repo. (h) The card states "started from Quick Ask; plan review skipped".
3. **Ask-derived cards are tainted, with a real mechanism (M5-3).** Server-assigned actors `research` and `ask-convert` (extend the board `ACTORS` validation); `maybeClaim` sets `untrusted` for `import`, `research` and `ask-convert`. The HTTP API never accepts `createdBy`. `untrusted` is **sticky**: editing the description does not clear it, only a human plan approval does. Every "Turn into work" card carries model-authored text and is `untrusted` (approval forced under every policy, `full-auto` included); the model text goes in a fenced untrusted block, the description keeps the user's own question. The fast-path card (`user-ask`) is not tainted (§2b-2d). Test: policy sweep (every policy × research-seeded card) forces approval; an edit does not clear it.
4. **Research argv and the probe contract (M5-4, Reviewer M5-3).** (a) The research argv is the existing `buildClaudeArgs` output with **exactly two** allowed deltas: the `--tools` value, and — only if the probe proves it necessary — `--allowedTools` entries that are exactly bare `WebSearch` and `WebFetch`. Everything else stays (`--permission-mode dontAsk`, `--permission-prompts none`, `--disallowedTools` credential list, `--strict-mcp-config`, `--disable-slash-commands`, the isolation flag, `--max-turns`). A snapshot test diffs the research argv against the plan/review/verify argv and asserts the delta. (b) **"Widening" is defined so the stop rule is unambiguous:** anything beyond (a) means STOP and report "not delivered": changing the permission mode, `--dangerously-skip-permissions`/`bypassPermissions`/`acceptEdits`, any allow rule naming Read, Bash, Edit, Write, MCP or a path-scoped rule, `--add-dir`, dropping any flag listed in (a), enabling user or project settings sources. (c) The probe runs the production research argv in an empty scratch cwd and records: CLI version, argv hash, the init tool list, whether WebSearch and a public-https WebFetch returned non-error results, that Bash/Edit/Write (and, for the default profile, Read/Grep/Glob) are absent from init, an attempted read of an absolute path outside the cwd (must be denied, repo-aware profile), and the loopback-canary result (§2b-6). The record is **add-only and bound to the CLI version** (same shape as the M2 verification records); the router offers `research` only with a passing record for the installed version (D11), otherwise "research: unverified, run the probe". `doctor --research-probe --yes` states it spends quota.
5. **Citation integrity rules (M5-7).** (a) The observed set is built only from **structured tool events** of this session (the `url` of WebFetch `tool_use` inputs — the raw event, not the truncated/redacted log line; the URLs in the structured WebSearch result); never from URLs inside fetched page content or model text (a hostile page could otherwise launder URLs into `verified`). The WebSearch parse is pinned to the shape recorded by the live probe; unparseable results contribute no URLs (all findings become `unverified`). (b) Two classes, `read` and `listed` (D10): a finding is `verified` only with ≥ 1 `read` source; a `listed` source is shown as "listed, not opened". (c) Normalisation is **one constant, tested function**: WHATWG parse; scheme `http`/`https` only; userinfo rejected; host lowercased and punycoded; default port and fragment dropped; path byte-exact (no case folding); query parameters sorted, dropping only a constant list (`utm_*`, `fbclid`, `gclid`, `msclkid`, `mc_cid`, `mc_eid`); matching is **exact** on the normalised string (no host-only or prefix matching); reasons recorded per demoted source (`not_observed`, `not_http`, `userinfo`, `no_source`). Redirects: the cited and fetched URLs may differ ⇒ the finding lands (safely) in `unverified` — documented. (d) The verified/unverified split is computed by Conductor after schema validation and stored with the record; the model's output cannot carry or restore the flag.
6. **WebFetch is a network client on the user's machine (M5-6).** (a) The probe includes a Conductor-owned loopback canary listener (ephemeral port, no secrets) and records whether WebFetch reaches it; (b) the research profile adds best-effort **deny** rules for loopback, link-local and metadata hostnames (`WebFetch(domain:localhost)`, `127.0.0.1`, `[::1]`, `169.254.169.254`, `metadata.google.internal`) **if** the CLI accepts domain-scoped deny rules (the probe records whether they work) — deny rules narrow the profile and are not widening; (c) the docs and the research panel state plainly that fetches run from this machine, can reach local-network services if the CLI does not block them, and that a web page can steer the agent to put content into later URLs; (d) the report lists **all** fetched URLs and search queries from the tool events (not only cited ones) and marks fetched URLs on non-cited hosts that carry a query string or a long path.
7. **Isolation flag and predicate (M5-8).** (a) Research requires `--safe-mode`; if `cfg.agents.claude.isolation === 'setting-sources'` (the fallback that loads project/local settings, which can carry hooks) the router **refuses `research` with the reason**. (b) `checkClaudeInit(init, { profile })` takes the exact allowed set per profile; web tools must be present for research and **absent** for plan/review/verify; `permissionMode === 'dontAsk'` and empty `mcp_servers`/`skills`/`slash_commands` are kept for both; a missing init event is a violation. (c) The predicate runs on the init event of **every** spawned CLI process of an ask, including corrective re-asks. Negative tests per profile, plus research init with `Task`, `TodoWrite`, `NotebookEdit` or any `mcp__*` tool, and a research session that produces no init.

### 2.7 Requirement coverage statement (V6)

## 6. Risks and Dependencies

- **Web content as an injection and exfiltration channel:** mitigated by tools without Bash/Edit/Write/MCP, an empty scratch cwd by default, the credential deny-list, structural citation checks, untrusted rendering, forced approval for seeded work; **residual:** a repo-aware opt-in can leak repository content in URLs — said in the UI and docs.

- **Snapshot cost:** `git archive` of a large repo; capped and refused beyond the limit.
- **Claude-only research:** a single provider; documented.

## Evidence used (reproducible)

- **E1. Plain `git archive | tar -x` recreates symlinks, absolute and relative, and a read through them leaves the snapshot.** PoC: a commit with `evil-link -> <dir outside>` and `rel-link -> ../../../../../etc/hosts`; after `git archive --format=tar <sha> | tar -x`, both links exist as symlinks and `cat out/evil-link/id_rsa` printed the planted outside file. M5-AC2 says "symlink in repo not followed"; with the plan's wording (`git archive` into a scratch dir) that test fails. The only protection today for Read through such a link is the credential deny list in `CLAUDE_DENIED_READS`, which does not cover arbitrary user files, and Cursor `ask` mode has no equivalent.
- **E2. `git archive` (git 2.49) itself rejects trees with `..` and `.git` entries** ("invalid path"), accepts option-like names (`-rf`) and names with spaces, and honours `.gitattributes` from the archived tree (`export-subst` expanded `$Format:%H$` in my PoC). So a hostile base commit makes the snapshot fail (acceptable, fail closed), but the extractor still has to handle names safely and cannot assume a byte-identical tree.
- **E3. Facts in the clone that the plans misstate or leave open:**
  - `buildClaudeArgs` already carries `--permission-prompts none` and a configurable `isolation: 'safe-mode' | 'setting-sources'` (fallback `--setting-sources project,local`, which loads project settings, and project settings can carry hooks). The M5 argv list omits `--permission-prompts none` and names `--safe-mode` unconditionally.
  - `summarizeInput` (the log-line builder) drops WebFetch's `url` (it reads `file_path|path|pattern|command|query`) and truncates to 300 characters after redaction. URL folding must therefore read the raw structured `tool_use` input, not the log text.
  - `maybeClaim` sets `untrusted` only when `item.createdBy === 'import'` (`engine.ts:354`); approval is forced by `run.untrusted` (`stages.ts:529`); the re-plan rule uses `untrusted && !approvedBy` (`engine.ts:425`). The plan's "creates a work card with `untrusted: true`" has no mechanism today; a `createdBy` actor must carry it.
  - There is no URL target in `OPEN_TARGETS` (`open.ts`); the "existing https allow-list `open` path" in M5 does not exist. External links in the UI are plain anchors built by `safeHttp` with `rel="noopener noreferrer"` (`ui/app.js:1539`), and `http.ts:19` sends `Referrer-Policy: no-referrer`.
  - `ensureRealDir` creates directories with `mkdirSync(cur)` and no mode (permissions then depend on umask; confinement comes from the 0700 home root). The M4/M5 text says "0700 via `ensureRealDir`", which the helper does not enforce.
  - `POST /auth` (form-encoded OTP, single use, 60 s TTL, 24-byte random token) already exists for exactly the reason in the code comment (H4: no OTP on a command line). The M7 plan loads `GET /auth?otp=...` instead.
  - `isProtectedPath` is already case-insensitive and matches `.git*`; Windows-specific normalisation is not there.
  - Dependency installs (`npm ci`, `pnpm install --frozen-lockfile`, `yarn install ...`) run without `--ignore-scripts` (`worktree.ts:410-419`). Pre-existing; relevant to M7 only for the Windows `.cmd` route.

## M5 conditions

### BEFORE-EDIT (binding plan text)

**M5-1 [BEFORE-EDIT, High] Snapshot construction (E1, E2).**
(a) The Quick Ask snapshot is built by Conductor code, not by piping `git archive` into the system `tar`. Either read `git ls-tree -r -z --long <40-hex commit>` plus `git cat-file --batch`, or parse the `git archive --format=tar` byte stream with a Conductor-owned reader. In both cases only **regular files** are written (`O_CREAT|O_EXCL|O_NOFOLLOW`, files 0600, dirs 0700). Symlinks (120000), gitlinks (160000), hardlinks, devices and fifos are not materialised; the answer states "N symlinks omitted".
(b) Entry names are validated: no `..`/`.`/empty segment, no absolute path, no control characters, no `.git` segment (case-insensitive), path length ≤ 1024, depth ≤ 64.
(c) The agent-config set is omitted from the snapshot (`.claude/`, `.cursor/`, `.codex/`, `.agents/`, `.husky/`, `.mcp.json`); markdown instruction files stay (same residual as Engineering read-only stages). The UI says "agent configuration omitted".
(d) Caps are measured **before** writing from the `ls-tree --long` sizes: total ≤ 500 MB, files ≤ 200 000, single blob ≤ 25 MB (larger blobs skipped and counted). Over the total cap the ask is refused with "too large for Quick Ask".
(e) The commit is resolved once to a 40-hex id (`rev-parse --verify --end-of-options refs/heads/<branch>^{commit}`), and only that id is passed on. Every git call uses the hardened env (`GIT_CONFIG_GLOBAL` to the null device, `GIT_CONFIG_NOSYSTEM=1`, `GIT_TERMINAL_PROMPT=0`, `GIT_NO_LAZY_FETCH=1` so a partial clone cannot fetch from a remote through a "local" read, `--` before any path).
(f) The AC2 test plants a symlink to a canary file outside the snapshot and asserts the canary is unreachable both by `readFileSync` through the snapshot path and by the fake agent's Read.

**M5-2 [BEFORE-EDIT, High] Fast path trust rules.** The model decides `kind:'change'` after reading a repository snapshot that a hostile repo can influence; the fast path then starts a `--force` builder with plan review skipped. Binding rules:
(a) Only when the request carried `allowChange: true` (UI checkbox, default off, own-property boolean). Otherwise a `change` is only offered.
(b) The fast path skips plan review **only**. Approval goes through the single approval decision (today `approvalGate`, M6 `decideApproval`): `planApproval: manual|first`, `L`, protected paths, `untrusted`, M6 `approve-plan`/`manual-stages` and risk rules all still hold. It must not auto-approve over a policy that says hold.
(c) Eligibility is decided on the **planner's** plan (`complexity === 'S'`, `filesToChange` containing no protected path, no secret-looking path, no `.git*`, ≤ 3 files, each relative and normalised), not on `ASK_SCHEMA.change`. If the plan disagrees with the ask's claim, the run takes the normal approval path.
(d) The builder's task text is the user's literal question (fenced as task) plus the planner's plan as today. The ask model's `change.description` and `files` are not forwarded; they only seed eligibility.
(e) Because plan review is skipped, the post-build scope check is "diff ⊆ plan files" for **all** paths on a fast-path run (not only protected ones); a violation ends `needs_human`.
(f) `Run.fastPath`, `createdBy:'user-ask'` and `autoStart` are assigned only by server code. The card create/edit/import HTTP schemas reject or strip them (test: POST with each field).
(g) Limits: fast-path starts ≤ 5 per hour (ceiling 20), ≤ 1 running fast-path run per repo.
(h) The card states "started from Quick Ask; plan review skipped".

**M5-3 [BEFORE-EDIT, High] Ask-derived cards are tainted, with a real mechanism.** Add server-assigned actors `research` and `ask-convert` (extend the board `ACTORS` validation); `maybeClaim` sets `untrusted` for `import`, `research` and `ask-convert`. The HTTP API never accepts `createdBy`. `untrusted` is sticky: editing the description does not clear it, only a human plan approval does (the existing `unapproved` rule). Every "Turn into work" card (research report, Quick Ask answer, offered change) carries model-authored text and is therefore `untrusted` (approval forced under every policy, including `full-auto`). The model text goes in a fenced untrusted block; the description keeps the user's own question. The fast-path card (`user-ask`) is not tainted (M5-2 (d)). Test: policy sweep (every policy x research-seeded card) forces approval; an edit does not clear it.

**M5-4 [BEFORE-EDIT, High] The research argv and the `dontAsk` probe contract.**
(a) The research argv is the existing `buildClaudeArgs` output with exactly two deltas allowed: the `--tools` value (`Read,Grep,Glob,WebSearch,WebFetch`) and, only if the probe proves it necessary, `--allowedTools` entries that are exactly bare `WebSearch` and `WebFetch`. Everything else stays: `--permission-mode dontAsk`, `--permission-prompts none`, `--disallowedTools` credential list, `--strict-mcp-config`, `--disable-slash-commands`, the isolation flag, `--max-turns`. A snapshot test diffs research argv against the plan/review/verify argv and asserts the delta is exactly that.
(b) "Widening" is defined so the stop rule is unambiguous. Anything beyond (a) means STOP and report "not delivered": changing the permission mode, `--dangerously-skip-permissions`/`bypassPermissions`/`acceptEdits`, any allow rule naming Read, Bash, Edit, Write, MCP or a path-scoped rule, `--add-dir`, dropping any flag listed in (a), enabling user or project settings sources.
(c) The probe runs the production research argv in an empty scratch cwd and records: CLI version, argv hash, the init tool list, whether WebSearch and WebFetch (public https URL) returned non-error results, that Bash/Edit/Write are absent from init, and the loopback canary result (M5-6). The record is add-only, bound to the CLI version (same shape as the M2 verification records). The router offers `research` only with a passing record for the installed CLI version; otherwise "research: unverified, run the probe". The probe needs `--yes` and states it spends quota.

**M5-5 [BEFORE-EDIT, High] What the research prompt may contain.** The plan's default says "empty scratch cwd, nothing to leak" and, in the same bullet, that the redacted M4 pack goes into the prompt. A model that holds module names, script commands and file names can put them in a WebFetch URL, so the pack defeats the empty cwd. Binding text: the default research prompt is the user's question only. The M4 deterministic pack (never the LLM summaries or history digests) is added only when `repoAware: true`, together with the snapshot cwd (built by M5-1), under the same explicit UI statement.

**M5-6 [BEFORE-EDIT, Medium] WebFetch is a network client on the user's machine (SSRF, local services, exfiltration channel).** Conductor cannot filter it. Required: (a) the probe includes a Conductor-owned loopback canary listener (ephemeral port, no secrets) and records whether WebFetch reaches it; (b) the research profile adds best-effort deny rules for loopback, link-local and metadata hostnames (for example `WebFetch(domain:localhost)`, `127.0.0.1`, `[::1]`, `169.254.169.254`, `metadata.google.internal`) **if** the CLI accepts domain-scoped deny rules (the probe records whether they work); deny rules narrow the profile, they are not widening; (c) the docs and the research panel state plainly that fetches run from this machine, can reach local-network services if the CLI does not block them, and that a web page can steer the agent to put content into later URLs; (d) the report lists **all** fetched URLs and search queries from the tool events (not only cited ones) and marks fetched URLs on non-cited hosts that carry a query string or a long path. The user accepted URL leakage for the repo-aware opt-in; (c) and (d) extend the same acceptance to local services and make it auditable.

**M5-7 [BEFORE-EDIT, High] Citation integrity rules.**
(a) The observed set is built only from structured tool events of this session: the `url` of WebFetch `tool_use` inputs (raw event, not the truncated/redacted log line, see E3) and the URLs in the structured WebSearch result. Never from URLs that appear inside fetched page content or model text; otherwise a hostile page can launder arbitrary URLs ("see https://evil...") into `verified`. The WebSearch parse is pinned to the result shape recorded by the live probe; unparseable results contribute no URLs (all findings become `unverified`).
(b) Two classes: `read` (fetched) and `listed` (search result only). A finding is `verified` only if at least one source is `read`. A source that was only listed is shown as "listed, not opened". (Recommended; if Lead prefers `listed` counting as verified, the label "not opened" is still mandatory.)
(c) Normalisation is one constant, tested function: WHATWG parse; scheme `http`/`https` only; userinfo rejected; host lowercased and punycoded; default port and fragment dropped; path kept byte-exact (no case folding); query parameters sorted, dropping only a constant list (`utm_*`, `fbclid`, `gclid`, `msclkid`, `mc_cid`, `mc_eid`). Matching is exact on the normalised string: no host-only or prefix matching. Reasons recorded per demoted source (`not_observed`, `not_http`, `userinfo`, `no_source`).
(d) The verified/unverified split is computed by Conductor after schema validation and stored with the record; the model's output cannot carry or restore the flag. `quote` is labelled "model-reported, not checked against the page" (WebFetch returns processed content, so verbatim matching is unreliable).

**M5-8 [BEFORE-EDIT, Medium] Isolation flag and profile predicate.** (a) Research requires `--safe-mode`. If `cfg.agents.claude.isolation === 'setting-sources'` the router refuses `research` with the reason (that fallback loads project/local settings, which can carry hooks; the default scratch cwd has none, the repo-aware snapshot omits them by M5-1 (c), but the refusal removes the dependency on either). (b) `checkClaudeInit(init, { profile })` takes the exact allowed set per profile (research: `Read, Grep, Glob, WebSearch, WebFetch, StructuredOutput`); web tools must be present for research and **absent** for plan/review/verify; `permissionMode === 'dontAsk'`, empty `mcp_servers`/`skills`/`slash_commands` are kept for both; a missing init event is a violation. (c) The predicate runs on the init event of **every** spawned CLI process of an ask, including corrective re-asks. Negative tests per profile as the plan lists, plus: research init with `Task`, `TodoWrite`, `NotebookEdit` or any `mcp__*` tool, and a research session that produces no init.

### DURING

No `<img>` can be produced (the CSP also blocks remote images). No new server-side opener (see E3). Size and count caps in schema validation and again in the renderer (findings ≤ 50, sources per finding ≤ 10, string lengths); `__proto__`/`constructor` keys handled with own-property reads. The research-specific docs say that rendering is data-only.

**M5-10 [DURING commit 2, Medium] Ask store.** Ids `^ask-[0-9a-f]{16,32}$` validated at every API and read boundary; `repo` is a registered repo id, never a path. Directory created with an explicit 0700 (pass the mode; `ensureRealDir` does not set one), files 0600 through the durable atomic writer. Load validates shape and caps (file read cap 512 KB; answer ≤ 20 000; research report ≤ 200 KB; events ≤ 200 lines x 600 chars) and quarantines violations as `*.corrupt-<ts>`. `index.json` pruning deletes the pruned record files. Add `DELETE /api/asks/:id` (CSRF) because records hold web text and user questions. `convert` is idempotent (`idemKey = ask id`) and allowed only for `status:'done'`. Event lines and stored results go through `redact`; the question is stored as typed and never logged.

**M5-11 [DURING commit 3/5, Medium] Limits and lifecycle.** `asksPerHour` (20, ceiling 60) and `researchPerDay` (5, ceiling 20) are persisted so a restart does not reset them; global concurrent asks ≤ 2, research ≤ 1 per provider; per-ask hard wall clock (quick 5 min, research 20 min) and `--max-turns` ceiling 60; ceilings are code constants that config cannot lift; breach returns 429 naming the limit. Cancel kills the process group and deletes the scratch dir; shutdown cancels running asks; scratch dirs are `mkdtemp` under a Conductor-owned 0700 parent, deleted in `finally` on success, failure and abort, and swept at startup (owned, prefixed, older than one hour).

**M5-12 [DURING commit 2, Medium] API strictness.** Strict bodies (`question` string ≤ 4000, `mode` enum, booleans own-property true/false, unknown keys rejected); CSRF and Sec-Fetch rules unchanged; ids validated before any path; SSE `ask` events carry redacted lines only; negative tests for `createdBy`, `fastPath`, `autoStart`, `untrusted` and `repo` as a path on `/api/ask` and the card endpoints.

**M5-13 [DURING commit 1/2, Medium] `callAgent` invariants.** Ask and research calls assert `cwd` is under the scratch root (never the user's checkout); no ask code path can reach the envelope or `runBuild` (static test; a builder only starts via a board card); URL folding and redaction live in the shared event path, with the raw event preserved for folding only.

**M5-14 [DURING commit 2, Low] Provider tiers.** Quick Ask on Cursor `ask` or Codex read-only shows the tier label; neither has web tools, so the only egress channel for an ask is the user-visible answer. Research stays Claude-only and `needs-network`; offline refusal only when the probe says `offline` (not `unknown`).

**M5-15 [DURING commit 5, Low] Honesty statements** (docs and the research panel): URLs can carry content; fetches run from this machine; verified means "URL was observed in this session", not "claim is true"; Claude keeps its own session transcript (including web content) in the user's Claude home; Quick Ask answers are based on `branch @ sha`, not the working tree.

## M7 conditions

### BEFORE-EDIT (binding plan text)

**M7-1 [BEFORE-EDIT, High] Session hand-off.** The plan loads `GET /auth?otp=...`. Replace with: the sidecar binds `127.0.0.1` port **0** and reports the port it actually holds; it mints one OTP (existing 60 s TTL, single use) and sends `{port, otp}` to main over the `utilityProcess` MessagePort; main loads `http://127.0.0.1:<port>/auth` with `loadURL(..., { postData: [rawData "otp=<otp>"], extraHeaders: form content type })` so the existing `POST /auth` route is used (no new route) and the OTP never appears in a URL (history, `did-navigate`, crash data, Referer) or on any command line. Desktop mode never attaches to an already-running server or a configured fixed port (a squatter on that port would receive the OTP). The renderer session uses a **non-persistent** partition (no `persist:` prefix) so the session cookie never reaches disk; navigation history is cleared after sign-in.

**M7-2 [BEFORE-EDIT, High] Frozen Electron hardening spec** (extends F-9). `BrowserWindow`: `contextIsolation:true`, `sandbox:true`, `nodeIntegration:false` (also for workers and subframes), `webviewTag:false`, `webSecurity:true`, `allowRunningInsecureContent:false`, `experimentalFeatures:false`, `devTools:false` in packaged builds, `navigateOnDragDrop:false`, non-persistent partition; `app.enableSandbox()` before ready. Applied to **every** webContents via `web-contents-created`: `will-navigate`, `will-redirect` and `will-frame-navigate` allow only the exact parsed origin `http://127.0.0.1:<port>`; `setWindowOpenHandler` always denies and, for a user-initiated `https:` URL without userinfo and ≤ 2048 characters, hands it to `shell.openExternal`; `will-attach-webview` prevented; permission request, permission check and device-permission handlers deny everything; `session.webRequest.onBeforeRequest` cancels anything outside the exact origin (including `ws:`/`wss:`); no custom protocol, no `setAsDefaultProtocolClient`, no file associations, no `file://` loads. Fuses set at package time (names per `@electron/fuses`, verified against the pinned version): `RunAsNode` off, `EnableNodeOptionsEnvironmentVariable` off, `EnableNodeCliInspectArguments` off, `EnableCookieEncryption` on, `OnlyLoadAppFromAsar` on, `EnableEmbeddedAsarIntegrityValidation` on, `GrantFileProtocolExtraPrivileges` off. No `--remote-debugging-port`, `--inspect` or `appendSwitch` use (static test). The sidecar is `utilityProcess.fork` only; the plan's alternative (`ELECTRON_RUN_AS_NODE`) is dropped (the fuse makes it unusable anyway). The Electron version is pinned to a current supported line at download time and recorded.

**M7-3 [BEFORE-EDIT, High] IPC and consent.** Every `ipcMain.handle` validates that the sender is the main frame of the main window and that its origin equals the pinned origin, validates the payload against a schema with a size cap, and the channel list is exactly the documented set. Prefer **no preload**: the dashboard is a web app and links go through the window-open handler. If a preload is unavoidable it exposes individually named functions through `contextBridge` (no raw `ipcRenderer`, no `send(channel, ...)` passthrough, no event objects). Consent for plaintext storage is a native `dialog.showMessageBox` in main (never a boolean sent by the renderer). The diagnostics path comes from a native `showSaveDialog` in main; the renderer supplies no path.

**M7-4 [BEFORE-EDIT, High] Secret handling.** `safeStorage` lives in main only and is never reachable from preload. Secrets travel main to sidecar over the MessagePort only, are held in memory, are registered with the redactor on arrival, and are written nowhere by the sidecar (the existing per-run allow-listed child env stays the only place a provider secret appears). The encrypted blob file is 0600 in `userData`, versioned, length-capped; a `decryptString` failure is treated as "absent", never as a plaintext fallback. `isEncryptionAvailable()` false, or a Linux backend of `basic_text`/`unknown`, means refuse to store, with a single exception: the native-dialog consent, which records the backend name and asks again when the backend changes. The same rule covers the CLI: plaintext fallback (including the Linux "0600 file with notice" in the strategy table) requires explicit consent recorded by a TTY confirm in the CLI, and **cannot be set through the HTTP API**. SECRETS.md must say what this protects (other users, offline disk theft) and what it does not (any other process of the same user can decrypt DPAPI data or is prompted by Keychain), so it is not claimed stronger than the 0600 file against same-user malware. Linux `secret-tool` is invoked by absolute path with constant attributes and the secret on stdin.

**M7-5 [BEFORE-EDIT, High] Windows executable resolution.** On Windows no command is spawned by bare name. Resolve each needed executable once at startup to an absolute path from system directories and absolute `PATH` entries that exist and are **not** inside any registered repo, worktree, Conductor home or temp directory; never the cwd or `.`. Spawn by that absolute path only; the strategy runner refuses bare names (static test over `src/`). Child `PATH` contains absolute entries only and child `PATHEXT` is `.COM;.EXE`. Reason: the Windows process-lookup order includes the child's working directory (libuv/CreateProcess behaviour, documented but not verified here, no Windows host), so a hostile repo containing `git.exe`, `node.exe` or `claude.exe` at its root would otherwise run when Conductor starts a command with that repo as cwd.

**M7-6 [BEFORE-EDIT, High] Windows `.cmd`/`.bat` and the gate grammar.** (a) No `shell:true` anywhere (static test). (b) A `.cmd`/`.bat` target is never spawned with arguments derived from agent, schema, repo or card text (CVE-2024-27980 class). npm shims are resolved by parsing the shim to an absolute `node.exe` + script pair (both inside the shim's directory); a shim that does not parse is refused with "unavailable on Windows (unverified)". (c) Gate/install commands are argv-only: each token must match a conservative whitelist (letters, digits, `_ @ + = : , . / \ -`); any `& | ; < > ^ % ! ( ) " ' backtick $ newline NUL` makes the command refused with "write one command per gate entry". (d) If a `.cmd` target is unavoidable (for example `npm`), Conductor writes a command file into a private 0700 temp dir (`O_EXCL`) containing only absolute path + whitelisted tokens, runs it as the absolute `%SystemRoot%\System32\cmd.exe` with `/d /s /c "<abs file>"`, and deletes it afterwards; no model or repo text is on the cmd command line.

**M7-7 [BEFORE-EDIT, High] Build capability gating.** The host self-test record is add-only and bound to `{os, arch, hostname hash, gitPath, gitVersion, hash of the env/stub generation code, conductor version}`; any change invalidates it, and a record copied from another machine (roaming profile, synced home) does not satisfy it. The self-test actually attempts a push to a scratch bare repo with the guard env and proves: the push is refused, no ref moved in the bare repo, no credential helper or askpass canary was invoked, and the effective config under the guard env lists no origin outside the guard set (on Windows this must show that the Git for Windows **system** config, which commonly sets `credential.helper`, is not loaded). A platform whose self-test cannot run is `unverified` and `build` is blocked with the reason shown in the UI.

**M7-8 [BEFORE-EDIT, Medium] No control channel.** `win32` control is `none`; the strategy never creates a named pipe or socket path on Windows (static test). Desktop mode never calls `listenControl`. The CLI commands that depend on it (`open`, `stop`) print that reason on Windows. (Named pipes created by Node get a default DACL that is not user-only; a pipe is out until it has an explicit DACL, as the plan already says.)

**M7-9 [BEFORE-EDIT, Medium] Windows private-dir and path semantics.** POSIX mode bits do not exist there. The strategy provides `ensurePrivateDir`: the Conductor home must resolve under the user profile (`%LOCALAPPDATA%`); `CONDUCTOR_HOME` elsewhere is refused unless the user explicitly confirms; docs say no `chmod`-level guarantee. Repo and worktree paths: refuse UNC (`\\host\share`, `\\?\UNC\`) because touching an attacker-named share leaks NTLM credentials; reject reserved device names, trailing dots/spaces, `:` (alternate data streams) and 8.3 `~N` segments in plan-declared paths; compare case-insensitively; long-path refusal with a reason; junction, symlink and `\\?\` cases in the path-rule corpus. Also pass an explicit 0700 mode in `ensureRealDir` on POSIX (E3).

**M7-10 [BEFORE-EDIT, Medium] Download gate and supply chain (D4).** The permission request in chat names each artifact: Electron (exact version and expected SHA-256), electron-builder, `@electron/fuses`, NSIS/fpm tool bundles, the Docker image (pinned by `@sha256:` digest, never a tag) and approximate sizes and source hosts. Nothing is downloaded or installed before a yes in chat; M7a needs none. `desktop/` has its own `package.json` with exact versions and a committed lockfile with integrity hashes; install is `npm ci`; the root `package.json` keeps zero `dependencies` (test) and `src/` never imports desktop packages. ## M3, M4, M6 skim

### M3 (task graph): no blocker

- **M3-S1 [Medium] Post-approval model text reaches the builder.** Analysis-item notes (`<item-notes>`) are produced after the plan was approved, from a read-only agent that read repository content, and are fenced into the prompts of build-class dependents. That conflicts with the M4 binding rule "LLM text is never placed in a builder prompt" unless the plan says the M4 rule is about cross-run stores. State it: notes are allowed in builder prompts only as run-local, fenced, capped data (summary ≤ 4 KB, decisions ≤ 10 x 200 characters) with wording that the approved item objective and file list are the only instructions; protected-path, scope and secret scans stay the backstop; notes are visible on the card.
- **M3-S2 [Medium] Crash-adopt marker is forgeable.** A `--force` builder can create a commit with another item's marker and any author string. Adopt only if the HEAD commit's parent equals `startHead` (exactly one new commit), the tree is clean, and the message carries a per-attempt nonce recorded in the run record; never adopt analysis items; **re-run the item's gates on adopt** (adopted is not gated). Extend the forge test to a builder-made forged commit.
- **M3-S3 [Medium] `attributeBug` uses a model-supplied `file`.** Accept it only if it is a member of `git diff --name-only <baseSha>..HEAD`; pass it after `--` with literal pathspecs (`--literal-pathspecs`, so `:(...)` magic cannot widen the match); commit ids are 40-hex.
- **M3-S4 [Low] Strings from items.** Item ids/titles in commit messages and subtask cards are single-line, control and bidi characters stripped, length-capped; a subtask card deleted by a human must not make the projection loop throw or recreate it.
- **M3-S5 [Low] Limits text is inconsistent.** The validator caps at 12 items while the config range is 1 to 20; make 12 the hard v2.0 ceiling. Cap the total size of a build-item prompt (notes included).

### M4 (context engine, offline)

- **M4-S1 [Medium, plan text before edit] Scanner git hygiene.** All scanner git calls use the hardened env, `GIT_NO_LAZY_FETCH=1` (a partial clone would otherwise fetch from a remote, with credential helpers, during a "local" scan), no textconv or filters, `--end-of-options` and 40-hex ids; use `cat-file --batch`/`--batch-check` instead of one process per module or blob; cap spawns and wall time per scan.
- **M4-S2 [Medium, plan text before edit] Offline liveness.** The 24 h ceiling must be cumulative per run (not per episode), plus an episode cap (for example 20) so a CLI that keeps reporting network errors while the probe says online cannot pause and resume forever with refunded attempts.

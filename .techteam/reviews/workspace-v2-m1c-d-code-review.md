## Part 2 — M1c

### `migrate.ts` — what holds
Read-only open of v1 (`RunStore` readOnly, hashes of every file read), dry run writes nothing, backup first (outside both homes, symlinks never followed, credentials/logs excluded, skipped items reported), staged in a sibling folder, validated by reopening with the v2 loaders (board, run store, config), publish by one `rename`, staging removed on every error path, target must be absent or an empty v2 skeleton, in-flight v1 runs (`queued/running/paused/failed`) become `needs_human` with an explicit note so v2 never starts the same work twice, `assignedPickup` runs `untrusted`, v1 worktree/branch/base never reused, pending Linear effects dropped, artifact copies hash-verified against the bytes read, invalid-shaped data rejected by the board loaders, the Keychain entry untouched. The tests cover dry run, apply, refusals, K7(i), four SIGKILL points and oversized text.

### Blocking
**B1 (M1c) — the importer builds filesystem paths from a value inside `run.json` before validating it.** `migrate.ts` step 1 does `join(from, 'runs', r.key)` with `r.key` taken from the file *content*; `planImport`'s `KEY_RE` check comes later. Reproduced: a v1 `runs/BAR-403/run.json` with `"key": "../../../nonexistent-dir"` makes `migrate` (even the dry run) die with a raw `ENOENT scandir '<path outside the v1 folder>'` — it reads outside the v1 folder, aborts the whole import and leaks the resolved path; a `run.json` whose key does not match its directory (`BAR-401` claiming `BAR-363`) silently borrows that other run's artifacts and ends up as a bogus `BAR-100363` card. The plan's own test list says "hostile imported keys rejected by `KEY_RE`"; the shipped "hostile v1 data" test only exercises an invalid *directory* name, which `RunStore.list()` already filters. Required: take identity from the **directory name** (validate it with the importer `KEY_RE`), skip a run whose `key` differs from its directory with a warning, never join a content-derived string into a path, and add tests with a traversal key and a mismatched key.

**B2 (M1c) — K7(i) is only partly true, and unreadable runs vanish silently.** (a) `RunStore.list()` parses `run.json` once, then the loop re-reads each `run.json` later to take its hash (after reading every earlier run's artifacts). A live v1 that rewrites `run.json` in that window is **not detected** (the recorded hash is of the newer bytes), so a stale picture is published — exactly what K7(i) promises to refuse; the shipped K7(i) test only appends to `events.ndjson` after staging. Read each `run.json` once and hash those same bytes (parse from them). (b) A v1 run directory whose `run.json` is corrupt or unreadable is dropped from the import with only a log line on stderr; the report (and the CLI output) never mentions it (reproduced with a truncated `runs/BAR-400/run.json`: "3 card(s)", no warning). The importer test's `assert.ok(r.warnings.some(…) || true)` is vacuous and its title promises a warning that does not exist. List every skipped folder in `report.warnings` and print them.

**B3 (M1c UI) — the Backlog / To do cards are re-created on every state event, so focus and clicks are lost.** `updateBoard()` does `reconcile(col.list, cl.map(idleCard))` and `idleCard()` builds brand-new `<li>`/buttons each time (the run cards use the keyed `B.cards` cache; these do not). Reproduced in the Browser pane against the demo (engine paused, one To do card): the card and its buttons were replaced **8 times in 15 s**. A keyboard user who tabs to *Park* loses focus within ~2 s; a mouse click that straddles a replacement is lost; screen readers re-announce the list. It is a regression from v1's keyed cards and violates the dashboard requirement "keyboard reachable, focus-visible" (`docs/API.md` UI #5). Required: key the idle cards (cache elements by `key` and update in place), or re-render only when the card list signature changes.

**B4 (M1c UI) — K4's "flag it on the dashboard" is not true: orphan and ignored cards are invisible.** `state.cards` includes cards in `active/needs_you/review` that have no run (with the engine's reason as `note`), but `updateBoard()` renders only the `backlog` and `todo` card columns, and the UI never reads `engine.ignored` (`grep ignored ui/app.js` → no match). So a card that lost its run, a card waiting on dependencies in another lane, an unsupported `ask/research` card, and a **tombstoned** run (`store.has()` is true so `cards()` drops it too) simply disappear from the dashboard. Required: surface `engine.ignored` (key + reason) as an attention list/banner and show run-less cards in any lane with their note.

## Part 3 — M1d

### Blocking
**B5 (M1d) — the docs state a safety control that does not exist for the common case.** `README.md` (lines 13, 39, 46) and `docs/ARCHITECTURE.md:47` say imported text/cards are "unverified" and their plan "waits for your approval". In the code, `untrusted` is set (a) by the run migration only for `assignedPickup` runs and (b) at *claim* time for an imported card that has **no run**. Every imported card from `migrate` has a run record, so it is never claimed: my rehearsal shows BAR-363 with `untrusted: undefined`, and after Retry its plan would be auto-approved under the default policy. v1 had attribution-checked that text, so not forcing approval is defensible — but the docs must say what the code does (only runs that were picked up because they were assigned to you, and imported cards that have no run, wait), or the importer must set `untrusted` on every imported run. Pick one and make README, ARCHITECTURE and the importer note agree.

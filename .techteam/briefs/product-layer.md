## 3. Features
- **F1 Home composer** — one input; Auto/Ask/Build/Research pills; repo auto-match or menu; "Handled by" chip (tool · model · effort) with popover; results as a thread with progress steps; example lines, three equal-height mode cards with a "who" line, "Your tools" row, Recent. Replaces the mode-card dialogs; reuses existing services.
- **F2 Quick Ask inline** — answer in the thread, read-only snapshot, file citations, basis (branch @ sha). No task/worktree. "Turn into a task" = user's own words + the answer as an untrusted fenced note (forced approval).
- **F3 "Design the work"** — one line → repo check → brief (goal, approach, files, acceptance, risks) → ≤ 8 ordered parts with deps → user unticks → "Send N tasks to the board" creates linked cards. New read-only structured call with schema {title, summary, approach, files, acceptance, risks, parts[{title, summary, size S/M/L, files, deps}]}; one corrective re-ask, redacted, fenced as untrusted. Recommendation: brief-derived cards untrusted (forced approval).
- **F4 Deep Research intake** — research brief (key questions, scope, source types), Standard/Deep; "Send as a research task" starts the existing web-only research; report findings with Opened/Listed/Unverified sources; "Turn into an engineering plan" → forced-approval card. v2 keeps research in the asks store.
- **F5 Board upgrades** — hints/empty states/tooltips name the assigned tool (defaults unchanged: "Claude writes the plan", "Cursor writes the code", "Gates, then Claude checks"); card chips tool · account when ≥ 2 accounts (tooltip: account, model, effort, Fast/Thinking); "Restarted"/"Switched tool" chip with reason.
- **F6 Run mode: Per settings | Complete auto** — switch in Board header and top of Settings. Complete auto = effective policy `full-auto` + limit rule "next account, then another tool". Never overwrites the stored policy, never removes forced holds, never approves already-waiting plans (toast says how many still wait). Overridden Settings fields disabled with an explanation.
- **F7 Who does what: tool, model, effort** — seven rows (Quick Ask, Deep Research, Design the work, Write the plan, Review the plan, Build the code, Verify the result); tool + model + effort in the tool's own words (Claude "Effort", Codex "Reasoning effort", Cursor "Model effort"); "Runs as …" line from the same argv builder. Model options: "Tool default (…)", discovered models (F7a), "Custom model id…" validated by `^[A-Za-z0-9][A-Za-z0-9._:/-]{0,63}$`; Save refused with focus. Tool default names what the tool itself picks (Claude `default` entry's resolved model; Cursor `(current, default)`; Codex server default). Effort options = exactly the discovered model's levels; none for Cursor Auto/Composer. Fast/Thinking only where reported. Collapsed "Default model for each tool" replaces `agents.<tool>.model` (migrate); a tool switch (F8) uses that tool's default model. Tool change resets model; model change keeps effort if offered else nearest + one-line note; Fast/Thinking dropped if absent. CLI: Claude `--model <v> --effort <l>`; Codex `--model=<id>` + `-c model_reasoning_effort=<l>`; Cursor `--model <id>` composed `family[-thinking][-effort][-fast]` and must exist in the discovered list (fail closed). `model`, `effort`, `fast`, `thinking` in `roles[role]` with versioned migration; unset ⇒ argv byte-identical; strict `PUT /api/roles`. Proposed mapping: Quick Ask → `context`, Deep Research → `research`, Design the work → `requirements`/`architecture`, Write the plan → `planning`, Review → `review`, Build → `implementation` (+ debugging, documentation), Verify → `verification`.
